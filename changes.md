# Отчёт о прохождении производственной практики

## Введение

Производственная практика (технологическая (проектно-технологическая) практика) проходила в компании ООО «ДжетРуби Эйдженси». Руководство от предприятия осуществлял руководитель направления мобильной разработки. Период прохождения: с 29.06.2026 по 26.07.2026.

В рамках практики разрабатывалось мобильное Android-приложение, предназначенное для отображения расписания и результатов матчей английской Премьер-лиги. Приложение использует открытое REST API fixturedownload.com и включает два экрана: перечень матчей и страницу с подробной информацией о выбранном матче.

Цель практики заключалась в практическом освоении современного стека Android-разработки: языка Kotlin, библиотеки Retrofit для взаимодействия с сервером, Kotlin Coroutines для асинхронных операций, архитектурного подхода MVVM и библиотеки Jetpack Compose для построения пользовательского интерфейса.

За время практики был пройден полный цикл разработки приложения — от анализа технического задания до получения готового продукта: реализована сетевая часть, спроектирован интерфейс, добавлено локальное кеширование на базе Room, организована пагинация и написаны тесты. Результатом стало завершённое приложение, готовое к дальнейшему развитию и сопровождению.

## 1 О предприятии

ООО «ДжетРуби Эйдженси» занимается разработкой программного обеспечения, включая мобильные приложения под Android как для собственных продуктов, так и на заказ. Команда выполняет работы полным циклом: от сбора требований и проектирования архитектуры до разработки, тестирования и последующей технической поддержки.

В компании установлен гибридный график работы, допускается удалённая работа по согласованию с руководителем. Для совместной разработки применяется Git, для внутренних коммуникаций — корпоративный мессенджер.

## 2 Инструментарий

Ниже перечислены основные инструменты, использованные в ходе прохождения производственной практики.

Для нативной Android-разработки применялась официальная среда Android Studio, рекомендованная Google и распространяемая бесплатно. Она построена на базе IntelliJ IDEA от JetBrains, предоставляет полный набор средств для написания и отладки кода, использует систему сборки Gradle и позволяет запускать приложения на эмуляторах и физических устройствах под разными версиями Android.

Рисунок 1 – Интерфейс IDE Android Studio с проектом приложения

Для управления зависимостями и сборки применялась система Gradle с Kotlin DSL (build.gradle.kts). Макеты экранов и техническое задание были предоставлены в Figma. Контроль версий кода осуществлялся через Git.

## 3 Реализованные задачи

В данном разделе описаны задачи, выполненные в рамках индивидуального задания, и применённые подходы.

### 3.1 Получение и обработка данных о матчах

Согласно техническому заданию, приложение запрашивает список матчей английской Премьер-лиги через публичное REST API (GET-запрос по адресу https://fixturedownload.com/feed/json/epl-2023) и обрабатывает полученные данные.

Для выполнения запроса был создан интерфейс Retrofit-сервиса и единая точка сборки HTTP-клиента на базе OkHttp с конвертером Gson. Взаимодействие с источником данных вынесено в репозиторий, который выступает единственным источником истины (Single Source of Truth). Помимо сетевого слоя, репозиторий использует локальную базу данных Room, куда сохраняются загруженные данные. Это позволяет избежать повторных запросов при повторном открытии экранов, обеспечивает работу приложения без интернета (offline-first) и ускоряет загрузку интерфейса.

Поскольку сервер передаёт время матча в UTC, реализована вспомогательная функция, конвертирующая значение в локальный часовой пояс устройства перед отображением пользователю.

### 3.2 Экран списка матчей

Экран списка матчей свёрстан на Jetpack Compose. Каждый матч представлен карточкой, содержащей названия команд, счёт (либо прочерк для несыгранных встреч), дату и время проведения в локальном формате. Список поддерживает плавную подгрузку следующих страниц при прокрутке (пагинация). Реализован локальный поиск матча по названию команды — фильтрация выполняется по уже загруженным данным без дополнительных вызовов API.

Рисунок 2 – Экран списка матчей

Состояние экрана (загрузка, данные получены, ошибка) описывается отдельным классом состояния и транслируется из ViewModel во View через объект StateFlow. Это соответствует паттерну MVVM, реализует однонаправленный поток данных (Unidirectional Data Flow) и обеспечивает предсказуемое обновление интерфейса.

### 3.3 Экран деталей матча

При нажатии на карточку в списке срабатывает навигационный переход (Navigation Compose) на экран деталей. На нём отображаются названия команд, счёт, дата и время проведения в локальном времени, место проведения, номер тура и статус матча (сыгран / предстоит). Оба экрана обращаются к общему репозиторию, благодаря чему данные не запрашиваются повторно при переходе между экранами.

Рисунок 3 – Экран деталей матча

Для верификации бизнес-логики написаны модульные тесты: проверка корректности конвертации времени из UTC в локальное, проверка работы ViewModel (фильтрация при поиске, начальное состояние).

## Заключение

За время практики в ООО «ДжетРуби Эйдженси» разработано Android-приложение для просмотра расписания и результатов матчей английской Премьер-лиги в полном соответствии с техническим заданием. Данные загружаются с сервера через Retrofit с использованием корутин, архитектура построена по MVVM с разделением на репозиторий и ViewModel, интерфейс выполнен на Jetpack Compose и включает два экрана: список матчей и детальную информацию о матче. Дополнительно реализованы конвертация времени в часовой пояс устройства, локальный поиск, кеширование на базе Room, пагинация и набор модульных тестов.

Практика позволила закрепить и углубить компетенции в области Android-разработки, а также получить практический опыт проектирования архитектуры мобильного приложения на актуальном стеке технологий.
